# Установка нашего полигона с нуля

Команды выполняются от root **на хосте Proxmox**. Если 15 стендов уже готовы, используйте [эксплуатацию](docs/OPERATIONS.md): заново устанавливать их не нужно.

## 1. Проверить исходные условия

Нужны Proxmox VE 7 / Debian 11, Python 3.9+, узел `pve`, WAN `vmbr0` с адресом хоста `10.0.55.12/24` и шлюзом `10.0.55.1`. Хранилища уже должны существовать:

- `ssd`: тип `dir`, путь `/mnt/ssd`, контент `images`; перед стартом минимум 600 ГиБ свободного места.
- `VM_Disk`: тип `dir`, путь `/mnt/pve/VM_Disk`, для архивов и кэша.
- `local`: разрешён контент `iso`, для `Additional.iso`.

Инструкция не создаёт разделы, файловые системы и LVM. Точки монтирования не должны оказаться пустыми папками вместо подключённых дисков.

```bash
pveversion
hostname -s
pvesm status
findmnt /mnt/ssd
findmnt /mnt/pve/VM_Disk
ip -br -4 addr show vmbr0
ip -4 route show default
```

На время установки остановите другие развёртывания и изменения VMID/сетей. Диапазон **20000–21499**, пулы `DEMO_2_S1`–`DEMO_2_S15` и соответствующие мосты должны быть свободны. Старые стенды удалять не требуется.

## 2. Установить зависимости

Сначала обновите индексы, иначе возможны 404 по устаревшим ссылкам.

```bash
apt-get update
apt-get install -y git python3 jq expect tmux zstd curl wget whiptail openvswitch-switch apt-cacher-ng
systemctl enable --now openvswitch-switch
systemctl is-active openvswitch-switch
ovs-vsctl show
```

Продолжайте после успешной установки и `active`. Общее обновление Proxmox не требуется.

**Если apt-get update выдаёт 401 от enterprise.proxmox.com:** при отсутствии подписки сохраните копию соответствующего файла в `/etc/apt/sources.list.d/`, закомментируйте строку enterprise PVE и подключите строку `deb http://download.proxmox.com/debian/pve bullseye pve-no-subscription`. Не отключайте проверку подписей и не меняйте Debian bullseye на другую версию. Снова выполните `apt-get update`. После скачивания проекта аналогичный фикс доступен в меню `system → utils → apt`.

## 3. Скачать проект

Каталог назначения должен быть новым. Если уже есть установленный оркестратор, не удаляйте его ради повторного клонирования.

```bash
git clone https://github.com/urijzubkov78-crypto/proxmox-demo-lab.git /root/proxmox-auto-deploy
cd /root/proxmox-auto-deploy
chmod 700 core.sh menu.sh
install -m 600 config/spetsnaz.conf.example spetsnaz.conf
```

Проверьте [пример конфигурации](config/spetsnaz.conf.example): для нашего профиля нужны `IMG_FROM_DEMO_2="DEMO_1"`, `APT_MODE="proxy"` и порт `3142`. Мастер первого запуска не нужен: конфигурация уже создана. Это shell-файл, используйте только доверенные значения.

## 4. Сохранить реестр старых ВМ

На нашем сервере уже есть `/root/pre-it-spetsnaz/old-vms.tsv`, защита `protection=1` ранее была проверена у 96 ВМ. **Не перезаписывайте реестр.** Метаданные и защита помогают не перепутать объекты, но не являются копией дисков.

Если реестра нет и прежние стенды действительно находятся в пулах `DE_...`, создайте список без изменения ВМ:

```bash
mkdir -p /root/pre-it-spetsnaz
if [ ! -e /root/pre-it-spetsnaz/old-vms.tsv ]; then
    pvesh get /cluster/resources --type vm --output-format json \
      | jq -r '.[] | select(.type == "qemu") | select((.pool // "") | startswith("DE_")) | [.node,.vmid,.name,.pool] | @tsv' \
      | sort -k2,2n > /root/pre-it-spetsnaz/old-vms.tsv
fi
wc -l /root/pre-it-spetsnaz/old-vms.tsv
```

Сверьте состав со старыми пулами: другое название пула этот фильтр не найдёт. Только после сверки включите защиту перечисленных ВМ:

```bash
while IFS=$'\t' read -r node vmid name pool; do
    pvesh set "/nodes/$node/qemu/$vmid/config" --protection 1 || break
done < /root/pre-it-spetsnaz/old-vms.tsv
```

Защита не запрещает выключение и откат. Старый оркестратор не должен обслуживать новые пулы, новый — старые.

## 5. Загрузить образы и ISO

### Образы ВМ — через меню оркестратора

Встроенный загрузчик сам скачивает архив с Яндекс.Диска, распаковывает его и размещает `.vma.zst` в папке модуля. WinSCP и ручная распаковка для этого не нужны.

```bash
cd /root/proxmox-auto-deploy
./menu.sh
```

1. Выберите **Системные утилиты (`system`) → Утилиты хоста (`utils`) → Скачать бэкапы шаблонов (.vma.zst) по URL (`download`)**.
2. Вставьте публичную ссылку на **файл комплекта DEMO_1** из [README исходного оркестратора](https://github.com/elena777-int/proxmox-auto-deploy/blob/c4dd79dcc7c72a533a175c84345bbed201247592/README.md):

   ```text
   https://disk.yandex.ru/d/ZvQV7FGJoMop-Q
   ```

   На момент проверки ссылка ведёт на файл `DEMO_1_Bundle.tar`. Ссылка на папку с отдельными бэкапами для пункта `download` не подходит.
3. Имя папки модуля укажите **`DEMO_1`**. В нашем конфиге уже задано `IMG_DIR="/mnt/pve/VM_Disk/spetsnaz-images"`, поэтому результат попадёт в **`/mnt/pve/VM_Disk/spetsnaz-images/DEMO_1`**. Создавать папку вручную не требуется.
4. Дождитесь сообщения об успешной загрузке и списка образов. При обрыве обычной загрузки повторите тот же пункт с той же ссылкой — меню предложит докачку. Если выбрана потоковая распаковка без временного файла, после обрыва потребуется скачать заново.
5. Вернитесь из меню в консоль и продолжайте с пункта 6 этой инструкции. Развёртывание выполняется позже, после проверки готовности.

**Почему DEMO_1, хотя разворачиваем DEMO_2:** наш профиль использует `IMG_FROM_DEMO_2="DEMO_1"`. Своей папки `spetsnaz-images/DEMO_2` быть не должно: upstream предпочитает её даже при заданном `IMG_FROM_DEMO_2`. Ссылка на комплект DEMO_2 из авторского README для нашего варианта не используется.

Публичный архив автора может обновляться. Для точного повторения нашего полигона сохраните исходные семь архивов: финализатор рассчитан на классический комплект с EcoRouter, Ideco и слотами из `SLOTS`. Описанный в авторском README облегчённый DEMO_1 на Альт p11 имеет другой состав ОС и дисков; его совместимость с нашим финализатором не подтверждена.

В папке `/mnt/pve/VM_Disk/spetsnaz-images/DEMO_1` должны находиться семь архивов:

```text
ISP.vma.zst
HQ-RTR.vma.zst
BR-RTR.vma.zst
BR-FW.vma.zst
HQ-SRV.vma.zst
HQ-CLI.vma.zst
BR-SRV.vma.zst
```

В наших образах HQ-SRV содержит основной диск 40 ГиБ и два по 1 ГиБ; ожидаемые слоты указаны в `SLOTS` финализатора. На ISP, HQ-SRV, HQ-CLI, BR-SRV нужен установленный QEMU Guest Agent и параметр `agent: 1` в конфигурации ВМ. На EcoRouter и Ideco агент не требуется. Совместимость произвольных образов с другими дисками и контроллерами не гарантируется.

**Если архивы уже есть на флешке:** используйте в том же подменю **«Загрузить образы с USB-флешки» (`usb`)**. Для файлов в корне флешки укажите папку модуля `DEMO_1`; если файлы во вложенной папке, подготовьте на флешке каталог `DEMO_1` — загрузчик сохраняет вложенную структуру. При наличии готовых образов на сервере повторная загрузка не нужна; меню загрузки с Яндекс.Диска перед перезаписью спросит подтверждение.

### Additional.iso — через веб-интерфейс Proxmox

Через **pve → local → ISO Images → Upload** загрузите **Additional.iso**, предоставленный с материалами экзамена. Должно получиться `local:iso/Additional.iso`; метка внутри ISO — `Additional`. Другие ISO можно оставить. Скрипты не удаляют и не переименовывают их.

Встроенный загрузчик комплектов переносит только `.vma.zst`, поэтому ISO загружается отдельно. Оркестратор подключит его к HQ-SRV и BR-SRV при деплое, а финализатор настроит монтирование внутри гостевых ОС. Образы и ISO в GitHub не включены.

## 6. Настроить кэшер на хосте

Отдельный IP или контейнер не нужен — используется адрес Proxmox. Если кэшер уже настроен и проверен, сохраните действующую конфигурацию и проверьте адрес, порт и каталог. Не заменяйте её вслепую.

Для новой службы:

```bash
install -d -o apt-cacher-ng -g apt-cacher-ng -m 750 /mnt/pve/VM_Disk/apt-cache
install -m 644 config/apt-cacher-ng.conf.example /etc/apt-cacher-ng/zz-demo-lab.conf
systemctl enable apt-cacher-ng
systemctl restart apt-cacher-ng
systemctl is-active apt-cacher-ng
ss -ltnp | grep ':3142'
```

Проверьте, что другие `/etc/apt-cacher-ng/*.conf` не задают конфликтующие параметры. Пример — минимальный фрагмент, не точная копия живой конфигурации. TCP/3142 должен быть доступен из учебных сетей через настроенные студентами маршруты/NAT; в публичный интернет его не открывайте.

Дважды запросите один RPM с хоста:

```bash
RPM_URL='http://mirror.yandex.ru/altlinux/p10/branch/x86_64/RPMS.classic/apt-conf-branch-10.0-alt1.p10.1.x86_64.rpm'
for attempt in 1 2; do
    curl --fail --silent --show-error --noproxy '' \
      --proxy http://10.0.55.12:3142 --max-time 60 \
      -o /dev/null -w 'HTTP=%{http_code}, bytes=%{size_download}\n' "$RPM_URL"
done
find /mnt/pve/VM_Disk/apt-cache -type f -name '*.rpm' -printf '%P\t%s bytes\n'
```

Ожидаются HTTP 200 и ненулевой размер. Прежний RPM может исчезнуть при обновлении зеркала: тогда выберите существующий RPM той же ветки. Не отключайте проверки APT. Предварительный прогрев не нужен: кэш пополняется по мере занятий.

## 7. Проверить готовность к деплою

```bash
cd /root/proxmox-auto-deploy
python3 scripts/preflight_install.py
```

Проверка только читает конфигурацию, VMID всего кластера, пулы, мосты, остаточные тома, хранилища, семь архивов, метку ISO и службы. При наличии реестра старых ВМ проверяет их присутствие и защиту. Разберите ошибки до деплоя. Проверка предназначена **до первого стенда**: после начала развёртывания диапазон закономерно будет занят.

## 8. Развернуть через меню

```bash
./menu.sh
```

Выберите `deploy → развёртывание → DEMO_2`. Для пробы сначала укажите `1`. Проверьте `qm config 20005` и `qm config 20004`: у HQ-SRV должны быть три диска, у BR-FW — основной и EFI. RAW после восстановления допустим: конвертация выполняется следующим этапом. После успешной пробы тем же пунктом разверните **2–15**. Можно сразу выбрать `1–15`; порядок должен быть возрастающим.

- Хранилище — `ssd`, источник образов в выводе — `DEMO_1`.
- Оставляйте новые ВМ выключенными до финализации.
- Отдельный экспертный сетевой патч не применяйте: сеть исходно настраивают студенты.
- Память и ядра оставьте как в образах, если отдельно не проверяли уменьшение.
- Ожидаются ID `20001–20007`, `20101–20107`, …, `21401–21407`.

Профиль выполняет штатное восстановление, откладывает Day0 и создаёт добавляемые дополнительные диски в QCOW2. У qmrestore в Proxmox VE 7 нет параметра --format: RAW из архива конвертируются отдельно. Если свободный блок не соответствует номеру стенда, деплой остановится.

После ошибки посмотрите Tasks, конфигурацию и остаточные тома. Не удаляйте файлы дисков вручную и не делайте unlock во время восстановления. Сообщение «деплой завершён» само по себе не подтверждает готовность всех 105 ВМ — финализатор проверит состав.

## 9. Подготовить диски

Все 105 новых ВМ должны оставаться выключенными, без снимков и неизвестных Unused. Не запускайте одновременно другой оркестратор, финализатор или операции с этими дисками.

Сначала посмотрите план без изменений:

```bash
python3 scripts/prepare_disks.py
```

После проверки состава выполните конвертацию:

```bash
python3 -u scripts/prepare_disks.py --apply
```

Помощник работает строго с 15 пулами DEMO_2 и ожидаемыми VMID/ролями. Для каждого RAW он вызывает штатное `qm disk move ... --format qcow2 --delete 0` на то же файловое ssd. Исходник остаётся в Unused, пока новый диск не пройдёт проверку QCOW2, сравнение виртуального размера и полное `qemu-img compare` с RAW. Затем только этот записанный исходник удаляется через `qm disk unlink ... --idlist unusedN`. Неизвестные Unused, чужие диски, работающие ВМ и снимки вызывают остановку.

Нужно время и временное место: перед каждым диском проверяется запас не меньше его виртуального размера плюс 32 ГиБ. Операции последовательные, чтобы ограничить нагрузку. Cloud-init/CD-ROM пропускаются, EFI и два дополнительных диска HQ-SRV включены.

Журнал источников и подтверждений: `/root/pre-it-spetsnaz/demo2-disks/state.json`. Сохраните его. После ошибки проверьте Tasks и состояние; повтор той же команды продолжит по журналу. При неизвестном исходе операции не удаляйте тома вручную. До завершения конвертации финализатор не запускайте.

Это новый помощник для опубликованного проекта, проверенный на моделях ошибок и продолжения. Его реальная конвертация на этом сервере ещё не выполнялась. Он не заменяет независимую резервную копию, а сохранённый исходный архив остаётся источником повторного восстановления.

## 10. Выполнить финальную подготовку

Только для нового комплекта из 15 стендов до занятий:

```bash
cd /root/proxmox-auto-deploy
python3 -u finalize_demo2.py --workers 2
```

Для меньшей нагрузки укажите `--workers 1`. Скрипт:

1. Проверит пулы, имена, слоты, принадлежность QCOW2, отсутствие Unused и чужих снимков.
2. Подключит ISO к HQ-SRV и BR-SRV, если привод свободен.
3. Включит ISP, HQ-SRV, HQ-CLI и BR-SRV, дождётся гостевых агентов.
4. Запишет `/etc/apt/apt.conf.d/99spetsnaz-proxy.conf`, очистит старые списки APT, сохранив `lists/partial`.
5. Настроит `LABEL=Additional` в fstab серверов, монтирование в `/mnt/additional` только для чтения.
6. Штатно выключит и повторно запустит эти четыре ВМ для проверки после загрузки.
7. Выключит их, проверит 150 QCOW2 и создаст Day0 на всех 105 выключенных ВМ.

Роутеры и BR-FW для гостевого патча не включаются. Сеть, RAID и пакеты по заданиям не настраиваются. Скрипт не конвертирует диски и не удаляет Unused — при несоответствии остановится.

Дождитесь **общего** итога: `стендов 15/15; QCOW2 150/150; APT 60/60; ISO 30/30; Day0 105/105` и возврата приглашения оболочки. Строки «Стенд 15 ГОТОВ» самой по себе недостаточно.

`CACHE_DOWNLOAD=FAILED` на внутренних ВМ без адресов/маршрутов ожидаем. Это отдельно от успешного сохранения прокси и автомонтирования. После настройки сети доступ к `10.0.55.12:3142` нужно проверить повторно. Тест одного RPM не подтверждает работу всех репозиториев.

При ошибке обработка остановится, часть новых ВМ может остаться включённой. Читайте `/root/pre-it-spetsnaz/demo2-finalize/run.log`, проверьте Tasks и состояния. После исправления повторите ту же команду, сохраняя `state.json` и каталог подготовки: они нужны для продолжения и распознавания собственных снимков. Чужой Day0 не перезаписывается.

`repair_alt_apt.py` нужен только для прежней ошибки фрагмента без `.conf` и автоматически продолжает финализацию. При новой установке он не нужен.

## 11. Приёмка

```bash
python3 scripts/audit_demo2.py
pvesm status
df -h /mnt/ssd /mnt/pve/VM_Disk
```

Ожидаются 105 ВМ, 150 рабочих QCOW2, 30 ISO и 105 Day0. Cloud-init RAW размером 4 МиБ допустим. Финализатор проверяет гостевые настройки, аудит — только состав и конфигурации, без включения ВМ.

Пароли находятся только на сервере: `/root/proxmox-auto-deploy/credentials/deploy_DE_2.csv`. Не публикуйте его. Дальше используйте [эксплуатацию](docs/OPERATIONS.md) и [хендбук](docs/handbook-demo2.pdf). Финализатор не является ежедневным обслуживанием.
