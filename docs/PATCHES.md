- Исходные core.sh/menu.sh объявляют версию 0.7.9. Версия профиля: `demo2-lab-1.0.0`.

Вместо последнего добавлен новый scripts/prepare_disks.py с отдельными тестами. Локальные финализатор, ремонт APT и хендбук включены. Пароли, журналы и состояния не включены.

## Известные правки полигона

1. Выбор свободных сотен VMID начинается с 20000 вместо 10000.
2. Автоматический Day0 после восстановления отложен до финальной подготовки.
3. Фрагмент APT называется `99spetsnaz-proxy.conf`: файл без `.conf` наши образы не загружали.
4. `IMG_FROM_DEMO_2=DEMO_1`, хранилище, WAN и прокси заданы в примере конфигурации.
5. Финализатор использует логику apt_job(cache), режим proxy: фрагмент, apt-get clean, удаление файлов списков с сохранением lists/partial. Через QGA stdin проверяет завершение команды и эффективный прокси.
6. Финализатор настраивает ISO/fstab, проверяет результат после повторной загрузки, проверяет QCOW2 и создаёт Day0 после выключения. Есть один/два исполнителя и продолжение по файлу состояния.

## Улучшения опубликованной сборки

Подготовлены для новой установки, автоматически на действующий сервер не устанавливаются:

- Штатное qmrestore и отдельный помощник конвертации: `qm disk move --format qcow2 --delete 0`, затем проверка, сравнение и удаление только записанного отсоединённого RAW через `qm disk unlink`. Команды проверены по [руководству Proxmox VE 7](https://pve.proxmox.com/pve-docs-7/qm.1.html) и [исходнику API stable-7](https://git.proxmox.com/?p=qemu-server.git;a=blob;f=PVE/API2/Qemu.pm;hb=stable-7). У qmrestore параметра --format нет. Профиль рассчитан на dir, не LVM-thin. Добавляемые диски сразу создаются с format=qcow2.
- Из восстановления убран `--force 1`; добавлен pipefail для ошибки распаковки.
- Инвентарь VMID читается через jq по всему кластеру. При ошибке API нет перехода на неполный локальный список.
- Для DEMO_2 найденный свободный блок сверяется с номером стенда. При несовпадении деплой останавливается.
- Для DEMO выбран точный Additional.iso, как ожидает финализатор.
- Убран безусловный unlock после восстановления.
- Добавлены проверки перед установкой и аудит готовых стендов, без изменения ВМ.

Остальные операции upstream, включая удаление и управление снимками, сохранены. Следуйте инструкции для своего сценария.

## Проверка

Нужны Python 3.9+, Bash, patch и обычные Unix-утилиты. На Windows использовался Git Bash. Тесты работают с временными файлами и подменами команд; Proxmox не нужен.

```bash
bash -n core.sh
bash -n menu.sh
python3 tests/test_profile.py
python3 tests/test_prepare_disks.py
python3 tests/test_finalize_demo2.py
python3 tests/test_finalize_demo2_guest.py
python3 -m compileall -q finalize_demo2.py repair_alt_apt.py scripts
```

Конвертация проверяется на моделях всех 150 дисков: источник сохраняется до сравнения, ошибки проверки/сравнения не удаляют RAW, неизвестный исход перемещения/удаления сверяется при продолжении, посторонние Unused и снимки блокируют обработку. Проверяются также инвентарь и блоки VMID, параметры восстановления, оба сбоя pipeline, воспроизводимость патча, принадлежность дисков, 15 стендов / два исполнителя, повторный запуск, чужие/незавершённые снимки, ошибки QGA/памяти/диска, асинхронный QGA, fstab, read-only mount, .conf, эффективный прокси и отсутствие сети как отдельный результат.

Модели не заменяют восстановление реальных архивов и запуск на конкретной версии Proxmox. Новые preflight/audit прошли проверку синтаксиса, но на живом сервере в рамках публикации не запускались. Полная новая установка сборки пока не проверена; сначала проверьте один стенд по INSTALL.md.
