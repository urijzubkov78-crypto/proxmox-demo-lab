# Эксплуатация готового полигона

Готовые стенды заново устанавливать и финализировать не нужно. Публикация проекта не обновляет сервер.

## Проверить состояние

Скачайте проект в отдельный каталог, сохраняя живой оркестратор:

```bash
git clone https://github.com/urijzubkov78-crypto/proxmox-demo-lab.git /root/proxmox-demo-lab
cd /root/proxmox-demo-lab
python3 scripts/audit_demo2.py
```

Аудит читает 15 пулов DEMO_2, конфигурации, пути дисков и список снимков. Он не запускает ВМ, не выполняет гостевые команды и не меняет Day0. Ожидаются `105/105` ВМ, `150/150` QCOW2, `105/105` Day0, `30/30` ISO. Гостевые APT и автомонтирование им не проверяются; включённые ВМ допустимы.

## Начать занятие

1. Место: `pvesm status`, `df -h /mnt/ssd`; память: `free -h`.
2. Proxmox: `https://10.0.55.12:8006`, пул `DEMO_2_SN`.
3. Меню: `cd /root/proxmox-auto-deploy`, затем `./menu.sh`.
4. `power → каскадный старт → DEMO_2 → нужные номера`. Начните с небольшой группы, учитывая память.
5. Вход студента: `demo-2-sN@pve`; пароль — в `credentials/deploy_DE_2.csv` либо последнем CSV после ротации.

CSV содержит пароли Proxmox, не пароли ОС из образов. Старые пулы `DE_...` обслуживаются отдельно.

## Завершить и вернуть Day0

Сохраните результаты, штатно завершите гостевые ОС и дождитесь `stopped`. Меню «мягкое выключение» в закреплённом upstream допускает принудительную остановку после 15 секунд; для важных данных завершайте ОС изнутри.

Для новой попытки выключите семь ВМ выбранного стенда, выберите `state → откат → DEMO_2 → номер → Day0`. Проверьте семь успешных откатов. ВМ останутся выключенными; запуск — через `power`. Изменения после Day0 будут потеряны. Промежуточные снимки называйте отдельно, не перезаписывайте Day0.

## Диски и ISO

Рабочие диски, включая EFI BR-FW, — QCOW2. Маленькие cloud-init RAW допустимы. Unused — отсоединённый том с данными; сначала выясните происхождение, затем решайте об удалении.

На HQ-SRV два пустых дополнительных диска по 1 ГиБ: RAID и ФС создаёт студент. На HQ-SRV и BR-SRV ISO должен монтироваться только для чтения:

```bash
findmnt /mnt/additional
ls -lah /mnt/additional
apt-config shell SPZ_PROXY Acquire::http::Proxy
ip -br -4 addr
ip -4 route
```

## Кэшер

На хосте: `systemctl is-active apt-cacher-ng`, порт `10.0.55.12:3142`. В Альт: `Acquire::http::Proxy "http://10.0.55.12:3142";` в `/etc/apt/apt.conf.d/99spetsnaz-proxy.conf`.

Кэшер не создаёт сеть. Адреса, маршруты, NAT и доступ на TCP/3142 настраивают студенты. До этого отсутствие загрузки ожидаемо. Кэш заполняется автоматически, откат ВМ его не очищает. После перехода на HTTPS/FTP или другое зеркало проверяйте работу отдельно.

## Изменения и удаление

Финализатор и `repair_alt_apt.py` — разовая подготовка, не обычное обслуживание после начала занятий. Они привязаны к конкретным VMID и файлу состояния и не являются автоматической процедурой пересоздания одного стенда.

Перед заменой `core.sh`/`menu.sh` сохраните их и `spetsnaz.conf`, сравните местные правки с [PATCHES.md](PATCHES.md). Не делайте слепой git pull поверх рабочей папки: репозиторий не является точной копией всех живых файлов Proxmox.

Удаление — только штатным `danger → DEMO_2 → нужный номер` после сверки VMID и ненужности результатов. Реестр `/root/pre-it-spetsnaz/old-vms.tsv` и `protection=1` помогают сохранить старые ВМ; защита не запрещает выключение и откаты. Снимки хранятся вместе с ВМ и не заменяют отдельную копию при отказе хранилища.
